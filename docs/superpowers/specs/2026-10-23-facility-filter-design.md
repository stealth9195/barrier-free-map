# Trip For All — 편의시설 필터와 사전 수집 데이터 설계

작성일: 2026-10-23
선행 설계: `2026-10-23-barrier-free-map-design.md`

## 1. 목적

1. 사용자가 **장애인 편의시설 조건(주차, 접근로, 출입통로 등)을 칩으로 켜고 끄며** 여러 조건을 함께 걸어 장소를 찾는다.
2. 관광타입(관광지, 문화시설 …)은 **드롭다운**으로 고른다.
3. 배포 앱의 **느린 첫 화면(약 20초)** 을 없앤다. 원인은 미국 서버에서 data.go.kr 을 실시간 호출하는 것이므로, 앱 실행 중에는 API 를 호출하지 않는다.
4. 화면 이름을 **Trip For All** 로 바꾼다.

**성공 기준**
- 배포 앱 첫 화면이 콜드 스타트를 제외하고 API 대기 없이 바로 뜬다 (앱 코드에서 data.go.kr 호출 0회).
- "주차" + "엘리베이터" 칩을 켜면 두 정보가 모두 있는 장소만 지도·목록에 남고, 칩을 끄면 다시 늘어난다.
- 관광타입 드롭다운, 시군구(세부 설정), 검색어, 편의시설 칩이 함께 적용된다(AND).
- 검색어 "경사로" 로 편의시설 설명에 경사로가 적힌 장소를 찾을 수 있다.

## 2. 범위

**포함**
- 서울(areaCode=1) 전체 무장애 관광정보 + 장소별 무장애 상세를 미리 수집한 JSON 데이터셋
- 데이터셋 생성 스크립트 (로컬에서 실행, 결과 파일을 저장소에 커밋)
- 앱: 데이터셋 기반 목록·필터·상세, 관광타입 드롭다운, 편의시설 칩(다중 선택), 이름 변경

**제외 (YAGNI)**
- 서울 외 지역 (스크립트에 지역코드만 넘기면 추가 가능하도록만 만든다)
- 데이터 자동 갱신(정기 실행) — 수동으로 스크립트를 다시 돌린다
- 칩별 개수 표시, OR 조건, 편의시설 "없음" 판별 (값이 있으면 "있음" 으로 본다 — 서울 데이터 확인 결과 부정 표현은 거의 없음)

## 3. 데이터셋

**파일**: `dataset/seoul.json` (저장소에 커밋. `data/` 는 기존대로 gitignore)

```json
{
  "area_code": "1",
  "area_name": "서울",
  "built_at": "2026-10-23",
  "sigungu": [{"code": "1", "name": "강남구"}, ...],
  "places": [
    {"contentid": "...", "title": "...", "addr1": "...", "tel": "...",
     "contenttypeid": "12", "sigungucode": "23",
     "firstimage": "https://...", "firstimage2": "https://...",
     "mapx": 126.97, "mapy": 37.57,
     "barrier": {"parking": "장애인 주차장 있음", "route": "..."}}
  ]
}
```

- `barrier` 에는 값이 있는 필드만 넣는다. 값 안의 `<br>` 태그는 ` / ` 로 바꾼다.
- 좌표가 없거나 0 인 장소는 제외한다. 이미지 주소는 https 로 바꾼다(기존 `TourApi.search` 와 같은 처리).
- 예상 크기: 서울 약 300곳, 수백 KB.

**생성 스크립트**: `build_dataset.py [areaCode=1] [출력=dataset/seoul.json]`
- `TourApi` 를 재사용한다. 목록은 `areaBasedList2` 를 페이지(1000건) 단위로 끝까지, 상세는 장소마다 `detailWithTour2` 1회 (동시 3개, 실패 시 재시도 3회).
- 서울 기준 약 300 + α 회 호출 — 개발계정 일 1,000건 안에서 한 번에 끝난다.
- 상세 조회가 끝내 실패한 장소는 `barrier: {}` 로 넣고, 실패 개수를 출력한다.

## 4. 앱 변경

### 4.1 데이터 로딩
- `dataset.py`: `load_dataset(path) -> dict` 와 필터 함수 `filter_places(places, *, sigungu=None, content_type=None, facilities=(), keyword="") -> list` (Streamlit 비의존, 단위 테스트 대상).
  - `facilities`: 필드 키 목록. 모든 키가 `barrier` 에 있어야 통과(AND).
  - `keyword`: 공백 제거 후, 제목·주소·`barrier` 값 중 하나라도 포함하면 통과(대소문자 무시).
- `app.py` 는 `st.cache_data` 로 데이터셋을 한 번 읽는다. **앱에서는 data.go.kr 을 호출하지 않으므로 서비스키(`OPENAI_API_KEY`)가 필요 없다.** 필수 설정은 `KAKAO_JS_KEY` 하나.
- 데이터셋 파일이 없으면 `st.error` 로 `python build_dataset.py` 실행 안내 후 `st.stop()`.

### 4.2 화면
- 제목: **Trip For All**, 그 아래 캡션 "서울 무장애 관광 지도 · 데이터 기준일 YYYY-MM-DD". 브라우저 탭 제목도 Trip For All.
- 패널 구성(위→아래):
  1. 검색창(알약형) + 세부 설정 버튼 — 검색어는 이름·주소·편의시설 설명을 찾는다. placeholder: "장소나 편의시설로 검색해 보세요 (예: 경사로)"
  2. **관광타입 드롭다운** (`st.selectbox`): 전체 + 7종
  3. **편의시설 칩** (`st.pills`, `selection_mode="multi"`): 켜고 끌 수 있고 여러 개 선택 가능. 선택 시 기존 칩 스타일(검정 채움).
     - 칩 목록(10개): 주차, 대중교통, 접근로, 출입통로, 엘리베이터, 화장실, 휠체어 대여, 점자블록, 유모차, 수유실
  4. 지역 표시("서울 · 종로구"), 결과 수 "검색 결과 N곳"
  5. 상세 카드(선택 시) — 기존과 동일, 정보는 데이터셋의 `barrier` 사용
  6. 결과 카드 목록 — 관광타입 태그 + **편의시설 태그**(최대 4개, 넘치면 "+n"). 켜 둔 칩에 해당하는 태그는 파란색으로 강조.
- 세부 설정 창: 시도 선택 대신 **시군구 칩**만 표시(데이터셋의 `sigungu`). 선택하지 않으면 서울 전체.
- 결과가 0곳이면 "조건에 맞는 장소가 없어요. 편의시설 칩을 줄이거나 검색어를 바꿔 보세요."
- "상위 100건만 표시" 안내는 제거(데이터셋 전체를 표시).
- 필터가 바뀌면 선택 해제(기존 동작 유지).
- 지도: 기존과 동일(필터된 장소만 마커). 인포윈도우 태그도 데이터셋의 `barrier` 에서.

### 4.3 유지/정리
- `tour_api.py` 는 수집 스크립트 전용으로 남긴다. `TourApi` 에 페이지 단위 목록 조회가 필요하면 `area_based_page(area_code, page, rows=1000)` 를 추가한다.
- `config.py` 는 그대로(키 조회 순서 동일).
- 배포 Secrets 의 `OPENAI_API_KEY` 는 앱에서 쓰지 않게 되지만 남겨 두어도 무해하다.

## 5. 테스트
- `tests/test_dataset.py`: 각 필터 단독·조합(AND), 키워드가 barrier 값에서 매칭, 공백 키워드 무시, 빈 facilities, 파일 로딩.
- `tests/test_build_dataset.py`: 가짜 `TourApi` 로 페이지 반복, `<br>` 정리, 좌표 없는 장소 제외, 상세 실패 시 `barrier: {}`.
- `tests/test_app.py` 갱신: 임시 데이터셋 파일로 AppTest — 드롭다운·칩·검색어 필터, 칩 끄기, 제목 "Trip For All", 데이터셋 없음 안내, 서비스키 없이도 동작.
- 수동: 실제 키로 `build_dataset.py` 실행 → 로컬 화면 확인 → push 후 배포 화면 첫 로딩 시간 확인.

## 6. 위험
| 위험 | 대응 |
|---|---|
| 데이터가 수집 시점 기준 | 캡션에 기준일 표시, 스크립트 재실행으로 갱신 |
| 한도 초과로 수집 중단 | 실패 개수 출력, 다음 날 재실행 |
| 공개 저장소에 데이터 포함 | 이미지는 URL만 저장. 화면 캡션에 출처 "한국관광공사 무장애여행 정보" 표기. 이용 조건은 공공데이터포털 해당 API 페이지에서 사용자가 최종 확인 |
